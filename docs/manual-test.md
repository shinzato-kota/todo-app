# 手動テスト手順

JUnitでは検証できない動作（ブラウザ上のJavaScriptの動作、アプリの再起動、リンクによる画面遷移）を、手作業で確認するための手順。

実施した結果は [test-results/manual-test.md](test-results/manual-test.md) に記録している。

サーバー側の処理は `src/test/java` 配下のJUnitテストで検証している。

## 前提

1. `README.md` のセットアップ手順に従い、アプリを起動しておく
2. ブラウザで `http://localhost:8080/todo-app/tasks` を開く
3. ブラウザの開発者ツールを開き、「ネットワーク」タブの「キャッシュを無効にする」にチェックを入れる（修正前のJavaScriptやCSSが使われないようにするため）
4. 開発者ツールの設定の「スロットリング」で、「プロファイルを追加」を押す
5. プロファイル名に「手動テスト用」、ダウンロードに「1000」、アップロードに「1000」、レイテンシに「5000」を入力して保存する（通信を5秒遅らせる項目で使う）
6. もう一度「プロファイルを追加」を押す
7. プロファイル名に「手動テスト用（10秒）」、ダウンロードに「1000」、アップロードに「1000」、レイテンシに「10000」を入力して保存する（通信を10秒遅らせる項目で使う）
8. もう一度「プロファイルを追加」を押す
9. プロファイル名に「手動テスト用（20秒）」、ダウンロードに「1000」、アップロードに「1000」、レイテンシに「20000」を入力して保存する（通信を20秒遅らせる項目で使う）

各項目の手順1で、その項目のテストデータ用SQL（`db/manual-test/項目の番号.sql`）を実行する。
テストデータ用SQLは、タスクとカテゴリをすべて消してから、その項目で使うデータを入れる。
残しておきたいデータがあるときは、実行する前にバックアップを取る。
テストデータ用SQLは、リポジトリのフォルダーで次のコマンドを実行して流す（ユーザー名は、`README.md` のセットアップ手順3で作ったユーザー）。

```text
mariadb -u ユーザー名 -p -e "source db/manual-test/01.sql"
```

項目は、どの順でも実施できる。

## 手順

### 1. アプリを再起動しても、足したタスクとカテゴリが表示され、タスクは並び替えた後の順番で表示される

**テストデータ**（`db/manual-test/01.sql`）

- カテゴリ2件: 「仕事」「勉強」
- タスク3件（上から並ぶ順）: 「タスクA」（カテゴリ「仕事」）、「タスクB」（カテゴリ「勉強」）、「タスクC」（カテゴリなし）

**手順**

1. `db/manual-test/01.sql` を実行する
2. 一覧画面を再読み込みする
3. 「タスクA」の行の「≡」を押したまま、「タスクC」の行の下の線より下までドラッグして離す
4. 画面上部の「カテゴリ一覧」を押す
5. 「カテゴリ追加」を押す
6. カテゴリ名の欄に「確認用」と入力する
7. 「保存」を押す
8. 画面上部の「タスク一覧」を押す
9. 「タスク追加」を押す
10. タイトルの欄に「再起動確認」と入力する
11. カテゴリのプルダウンで「確認用」を選ぶ
12. 「保存」を押す
13. アプリを起動したターミナルで、Ctrl キーを押したまま C キーを押す
14. 同じターミナルで、`.\mvnw.cmd spring-boot:run` を実行する（macOS・Linux は `./mvnw spring-boot:run`）
15. ブラウザで一覧画面を再読み込みする
16. 画面上部の「カテゴリ一覧」を押す

**確かめること**

- 2-1: 表の行が、上から「タスクA」「タスクB」「タスクC」の順に並んでいる
- 3-1: 表の行が、上から「タスクB」「タスクC」「タスクA」の順に並んでいる
- 7-1: カテゴリ一覧の表に、「仕事」「勉強」「確認用」の3行がある
- 12-1: 表の行が、上から「タスクB」「タスクC」「タスクA」「再起動確認」の順に並んでいる
- 12-2: 「再起動確認」の行のカテゴリの列に「確認用」が表示されている
- 13-1: ターミナルの最後の行に、コマンドを入力できる表示（PS で始まる行など）が出る
- 14-1: ターミナルに「Started TodoAppApplication」を含む行が出る
- 15-1: 表の行が、上から「タスクB」「タスクC」「タスクA」「再起動確認」の順に並んでいる
- 15-2: 表の行のカテゴリの列が、「タスクB」は「勉強」、「タスクC」は空、「タスクA」は「仕事」、「再起動確認」は「確認用」になっている
- 16-1: カテゴリ一覧の表に、「仕事」「勉強」「確認用」の3行がある

- 6-1: 「ステータス確認」のプルダウンは「保留」のままで、背景が薄い灰色、文字が灰色
- 7-1: 画面の再読み込みが行われずに、「ステータス確認」のプルダウンの背景が「比べる行」と同じ白に戻る
- 7-2: タイトル「ステータス確認」に取り消し線が付き、文字が薄い灰色になる
- 7-3: 詳細「詳細の文」の文字が薄い灰色になり、取り消し線は付かない
- 8-1: プルダウンは「完了」のままで、7-1〜7-3 と同じ見た目
- 9-1: 画面の再読み込みが行われずに、タイトル「ステータス確認」が斜体になる
- 9-2: タイトルの取り消し線と薄い灰色の文字、詳細の薄い灰色の文字は、手順7の後のまま
- 10-1: プルダウンは「中止」のままで、9-1〜9-2 と同じ見た目
- 11-1: 画面の再読み込みが行われずに、タイトル「ステータス確認」の取り消し線と斜体がなくなる
- 11-2: タイトル「ステータス確認」の文字の色が、「比べる行」のタイトルと同じ黒になる
- 11-3: 詳細「詳細の文」の文字の色が、薄い灰色から、それより濃い灰色になる
- 11-4: 「ステータス確認」のプルダウンの背景が薄い青に、文字が濃い青に変わる
- 12-1: プルダウンは「進行中」のままで、11-1〜11-4 と同じ見た目
- 13-1: 画面の再読み込みが行われずに、「ステータス確認」のプルダウンの背景が「比べる行」と同じ白に戻る
- 14-1: 2行とも、ステータスのプルダウンが「未着手」で、背景が白い

### 3. ステータス変更のレスポンスを待つ間は、その行のステータスのプルダウンを開けない

**テストデータ**（`db/manual-test/03.sql`）

- タスク1件: 「通信確認」（未着手、期限・カテゴリなし、優先度「中」）

**手順**

1. `db/manual-test/03.sql` を実行する
2. 開発者ツールの「ネットワーク」タブを押す
3. 一覧画面を再読み込みする
4. 「ネットワーク」タブで、通信速度のプルダウン（「スロットリングなし」と表示されている）を押し、「手動テスト用」を選ぶ
5. 「通信確認」の行のステータスのプルダウンで、「進行中」を選ぶ
6. 手順5から5秒たつ前に、「通信確認」の行のステータスのプルダウンを押す

8. 「通信確認」の行のステータスのプルダウンを押す

**確かめること**

- 6-1: 選択肢の一覧が開かない
